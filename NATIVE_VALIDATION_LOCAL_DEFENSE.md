# Local defense validation

The feature was integrated into an original EveJS 261108.1 source tree with the unmodified Playerbots 0.2.142 overlay, then only this candidate was applied. A private disposable runtime used that assembled source, rather than the developer's full production modifications. No production data volume was mounted. The integration used a compatible dependency/image base; the complete original distribution was not rebuilt from scratch.

The public controlled-dependency suite contains 13 scripts covering coordination, legal targeting/scope, commands and strict configuration, adaptive policy, arrival estimates, cleanup, scheduler wake ownership, cooperative director yields, interruption arbitration and economy commit boundaries. Run instructions are in LOCAL_DEFENSE.md. These tests do not use player saves.

Representative native integration cases used an isolated copied test universe and explicitly prepared fixtures:

- Player-origin settled hostile EWAR creates an incident and native drone authorities accept lawful responders.
- Managed-bot-origin threats are classified independently; responder counterattacks do not recruit an opposing chain.
- Victim-only limited engagement does not grant responders attack rights. Suspect/criminal flags are read through native authorities and rights are rechecked per responder. Ordinary pirate NPC threats do not create rescue incidents.
- Natural threat expiry recalls drones and releases reservations. The retained original task subsequently kills and loots a native pirate NPC. Own deployed drones keep the fit valid, while a drone assigned to another controller cannot fill a missing slot.

The resumption scenario explicitly advances native adapter/operation steps using an accelerated native engine clock. It does not claim new graphical-client evidence or real-time durable-scheduler timing. Scheduler ownership and wake races are covered by controlled tests. Private fixture placement, generated ships and cleared test wars are setup only, not production behavior or economy-preservation assertions. No production save, character identifiers, certificates or local environment files are included in the public candidate.

The installation manifest and a private draft ZIP were rebuilt with the supported original compatibility source; source/add-on hashes and archive integrity were checked. The draft retains 0.2.142 solely for local build verification. The maintainer selects the eventual release version and published distribution artifact.

Independent follow-up review adds disabled/default routing and option-boundary regressions. Native validation is rerun on the corrected candidate, including an ordinary NPC combat case with default-disabled rescue settings and zero rescue events/reservations. Revision timing and scope are retained in the private review record; no graphical-client run is claimed.
